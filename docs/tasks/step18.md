# Step 18: Web message list rendering upgrade + ChatRoom decomposition

## Meta
- **Type**: ui
- **Components**: web
- **Wave**: 3 (parallel group — all steps of the same wave can run concurrently)
- **Depends on**: Step 9: Web data layer migration: TanStack Query, RSC prefetch, per-feature API modules
- **Unlocks**: Step 29: Web send pipeline UX: optimistic send, AI thinking, retry, infinite scroll
- **Size**: 1 PR (a few hours for one AI agent)

## Context
`web/src/features/messages/components/ChatRoom.tsx` is currently a god component: it owns data fetching, all mutation handlers (send, send-with-AI, regenerate), loading state, and the page chrome, all inlined in one `useState`/`useEffect` block. `MessageList.tsx` renders every message as a flat, ungrouped list with plain-text bubbles and hover-only timestamps, and always force-scrolls to the bottom on every update. Step 9 replaces the data-fetching internals (TanStack Query hooks, per-feature `api/` module) but explicitly leaves the component/rendering decomposition to this step. This step turns the transcript into a modern chat UI (markdown, grouping, day separators, smart scroll) and splits `ChatRoom` into a data-orchestration hook plus focused subcomponents so step 29's send-pipeline work (optimistic messages, retry, infinite scroll) lands on a clean structure instead of a monolith.

## Goal
`ChatRoom.tsx` becomes a thin composition of `ChatRoomHeader`, `MessageList`, and `MessageInput`, with all state/data orchestration extracted into a `useChatRoom` hook that consumes the TanStack Query hooks step 9 introduced. AI message bodies render as sanitized markdown with syntax-highlighted, copy-button-equipped code blocks. The transcript groups consecutive same-sender messages, inserts day separators between calendar days, always shows a dim timestamp (full datetime on hover via tooltip), and only auto-scrolls to the bottom when the user is already near it — otherwise a floating "New messages" pill appears and scrolls on click.

Extract the near-bottom threshold check into an exported pure function (e.g. `computeIsNearBottom(scrollTop, scrollHeight, clientHeight, thresholdPx = 120): boolean`) so it is unit-testable without a DOM.
- [x] Wire the hook into `MessageList.tsx`: attach `containerRef` to the scrollable `Box`, remove the old unconditional `endRef.current?.scrollIntoView` effect, and render a floating "New messages" pill (Chakra `Button`, rounded-full, positioned `position="absolute"` at the bottom-center of the list) when `hasNewMessages` is true; clicking it calls `scrollToBottom()`.
- [x] Add unit tests for `group-messages.ts` (grouping by sender/time-gap/day boundary, day-label output) and for `computeIsNearBottom` in `use-near-bottom-scroll.ts`, runnable via the project's Vitest setup (introduced in step 5/9) with `bunx vitest run`.

## Implementation notes
- Current files to modify: `web/src/features/messages/components/ChatRoom.tsx`, `web/src/features/messages/components/MessageList.tsx`. `web/src/features/messages/components/MessageInput.tsx` and `web/src/features/messages/components/ModelSelector.tsx` are unaffected in behavior — only wire them to whatever `useChatRoom` exposes (their prop contracts are unchanged: `onSend`, `onSendWithAI`, `models`).
- `useChatRoom` must consume step 9's per-feature TanStack Query hooks (query/mutation hooks under `web/src/features/messages/api/` or equivalent, as landed by step 9) instead of calling `apiClient` directly with `useState`/`useEffect`/`Promise.all` — do not reintroduce the manual `fetchData` pattern currently in `ChatRoom.tsx`. If step 9 already exposes a combined "room + messages + models" hook, `useChatRoom` may be a thin wrapper that only adds the send/regenerate handlers and `isRegenerating` local state; if step 9 exposes them as separate hooks, compose them here.
- `Message` type (post-Step-9: `web/src/features/messages/types.ts`): `{ id, room_id, sender_id, content, type: "human" | "ai", status: "completed" | "failed", sequence, created_at, updated_at }`. Grouping/day-separator logic keys off `type`, `sender_id`, and `created_at` only — no schema changes needed.
- Reuse existing UI primitives: `@/components/ui/tooltip` (`Tooltip`, already used pattern with `content` prop) for both the timestamp tooltip and the code-block copy tooltip; `@/components/ui/color-mode` (`useColorModeValue`) for the syntax-highlighter theme swap — do not use React state + manual media-query listening.
- Per `.claude/rules/chakra-ui.md`: prefer `@chakra-ui/react` components and style props (`Box`, `Flex`, `Text`, `Avatar.Root`, `Button`) over ad hoc `<div>`/className; only reach for a new snippet if a Chakra open-API component cannot express the customization. Do not add the `Prose` snippet (it assumes Tailwind typography, which this project does not use) — style markdown output with a `Box css={{ "& h1": {...}, "& code": {...} }}` block instead.
- New dependencies: run `cd web && bun add react-markdown remark-gfm react-syntax-highlighter && bun add -d @types/react-syntax-highlighter`. `react-syntax-highlighter`'s Prism build ships its own highlight styles (e.g. `oneLight`/`oneDark` from `react-syntax-highlighter/dist/esm/styles/prism`) — import only the two themes used, not the whole style bundle.
- `MessageBubble.tsx` keeps the existing failed-state styling (`red.50`/`red.700` bg/color, `AlertTriangle` icon, "AI response failed" label) and the regenerate/retry `Button` (`RefreshCw` icon, `loading`/`loadingText` props) exactly as in the current `MessageList.tsx`; only the body rendering (plain text → `MarkdownContent` for AI messages) and the timestamp treatment change.
- No DB or schema changes — this is a web-only rendering step.
- Conflict/ownership note: this step owns `ChatRoom.tsx`, `MessageList.tsx`, and all new message-item subcomponents for wave 3. Per the plan-wide ownership rotation, `MessageList`/`MessageInput` are next touched by step 29 (send pipeline) — keep `MessageList`'s prop contract (`messages`, `onRegenerate`, `isRegenerating`) stable so step 29 can extend it (e.g. adding optimistic/pending message states) without renegotiating this step's internals.
- English-only comments/identifiers throughout, per `CLAUDE.md`.
