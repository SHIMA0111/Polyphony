# Step 14: Rust gateway test harness: router oneshot + wiremock provider tests

## Meta
- **Type**: testing
- **Components**: llm-gateway
- **Wave**: 3 (parallel group — all steps of the same wave can run concurrently)
- **Depends on**: Step 3: Rust gateway domain/ports reshape (streaming+multimodal-ready) | Step 8: Rust gateway operational hardening
- **Unlocks**: Step 25: Rust: Anthropic provider adapter | Step 26: Rust: Gemini provider adapter | Step 27: Token estimation endpoint (gateway) + Go proxy | Step 43: Rust: streaming SSE for all providers + stream endpoint
- **Size**: 1 PR (a few hours for one AI agent)

## Context
Today `llm-gateway` only has module-level `#[cfg(test)]` unit tests: `domain/service.rs` tests `CompletionService` against a hand-rolled `MockProvider`, and `adapters/outbound/openai.rs` tests pure request/response mapping functions in isolation. Nothing exercises the assembled `axum::Router` end-to-end (real HTTP status codes, JSON error bodies, extractor rejections), and nothing exercises `OpenAIProvider`'s actual HTTP client behavior against a real (mocked) server — the existing `EnvKeyStore` tests even mutate process environment variables with `unsafe { std::env::set_var(...) }`, which does not scale once tests run concurrently across providers. Step 3 reshapes the domain (`thiserror`-based `DomainError` with a `RateLimited` variant and source chains, `async fn models()`, streaming-ready ports) and step 8 hardens the gateway operationally (retries, a readiness endpoint, and — critically for this step — replacing ad-hoc `std::env::var(...)` calls inside adapter constructors with an explicit, injectable per-adapter config struct). This step builds the one HTTP-level test harness (tower `oneshot` for the router, `wiremock` for the outbound OpenAI adapter) that steps 25, 26, and 43 will extend with new provider/streaming cases instead of inventing their own mocking approach.

## Goal
After this PR, `llm-gateway` has a deterministic, network-free integration test suite with two new test modules: one that drives the fully assembled `axum::Router` through `tower::util::ServiceExt::oneshot` to verify `/health`, `/ready`, `/models`, and `/completions` (including the full `DomainError` → HTTP status mapping matrix), and one that stands up a `wiremock::MockServer` in place of `api.openai.com` and drives `OpenAIProvider` through success, auth-failure, rate-limit, server-error, malformed-body, and timeout scenarios — all wired via config injection (constructor parameters / config struct fields pointed at the mock server's URI), never via mutating process environment variables. Both test modules serve as the canonical pattern later provider and streaming steps extend.

## Scope
- [ ] Add test-only dependencies to `llm-gateway/Cargo.toml` `[dev-dependencies]`: `tower = { version = "0.5", features = ["util"] }` (for `ServiceExt::oneshot`), `wiremock = "0.6"`, and `http-body-util = "0.1"` (for draining `axum::body::Body` / `http_body::Body` response bytes into a JSON value in assertions). Keep `tokio` dev-dependency's `test-util`/`full` features as-is (already present).
- [ ] Create `llm-gateway/tests/router_test.rs` as a Rust integration test binary that imports the crate's public router-building entry point (`adapters::inbound::rest::router::build_router`, extending its `AppState`/`CompletionUseCase` wiring as landed by step 3) and a local test double implementing `CompletionUseCase` (do not hit real providers). For each case, build a `Request`, call `router.clone().oneshot(request).await`, and assert on `response.status()` and the JSON body (via `http_body_util::BodyExt::collect`):
  - [ ] `GET /health` → `200 OK` with the existing `{"status": "ok"}` body shape.
  - [ ] `GET /ready` → `200 OK` when the injected test double reports ready; if step 8 gives `/ready` a "not ready" failure mode (e.g. no providers configured), add a second case asserting the corresponding non-200 status. Confirm the actual route path/behavior in the router file landed by step 8 before writing the assertion — do not guess the payload shape without checking.
  - [ ] `GET /models` → `200 OK` with a `ModelsResponseDto`-shaped body aggregating the test double's models.
  - [ ] `POST /completions` happy path → `200 OK` with a `CompletionResponseDto`-shaped body.
  - [ ] `POST /completions` with a model the test double doesn't recognize → `404 NOT_FOUND` (`DomainError::ModelNotFound` mapping).
  - [ ] `POST /completions` with an empty `messages` array → `400 BAD_REQUEST` (`DomainError::InvalidRequest` mapping).
  - [ ] `POST /completions` with a syntactically malformed JSON body → assert whatever status axum's `Json` extractor rejection actually produces (axum returns `422 UNPROCESSABLE_ENTITY` for body deserialization failures, distinct from the handler's own `400` for domain-level `InvalidRequest`) — run the test first and pin the assertion to the observed status, documenting why it differs from the handler's `400` case.
  - [ ] A test-double case returning `DomainError::Timeout` → `504 GATEWAY_TIMEOUT`.
  - [ ] A test-double case returning `DomainError::KeyNotFound` → `500 INTERNAL_SERVER_ERROR`.
  - [ ] A test-double case returning `DomainError::ProviderError` → `502 BAD_GATEWAY`.
  - [ ] A test-double case returning `DomainError::RateLimited` (added in step 3) → `429 TOO_MANY_REQUESTS`. If `llm-gateway/src/adapters/inbound/rest/handlers.rs`'s `AppError::into_response` match does not yet have an arm for `RateLimited` by the time step 3/8 land, add the minimal match arm mapping it to `StatusCode::TOO_MANY_REQUESTS` (and a `Retry-After` header if the variant carries a retry-after duration) — this is the only production-code change permitted in this step; everything else is test-only.
- [ ] Create `llm-gateway/tests/openai_provider_test.rs` as a second integration test binary. Use `wiremock::MockServer::start().await` to stand in for `https://api.openai.com`, and construct `OpenAIProvider` via the explicit config-injection API introduced in step 8 (the successor to today's `OpenAIProvider::new(key_store: Arc<dyn KeyStore>)` at `llm-gateway/src/adapters/outbound/openai.rs:37-54`, which currently reads `OPENAI_BASE_URL` via `std::env::var` internally) so that `base_url` is set to `mock_server.uri()` directly as a constructor/config argument. Do not call `std::env::set_var`/`remove_var` in these new tests. Cover:
  - [ ] `200 OK` success response (a realistic OpenAI chat-completion JSON fixture) → asserts the mapped `CompletionResponse` fields (id, model, choice content, usage) match `from_openai_response` semantics.
  - [ ] `401 Unauthorized` → maps to a provider/auth `DomainError` variant (whatever step 3 named it — `ProviderError` with the status embedded, or a dedicated variant if one was added) with the OpenAI error message surfaced in the error text.
  - [ ] `429 Too Many Requests` (with a `Retry-After` response header in the wiremock response) → maps to `DomainError::RateLimited`, asserting any retry-after value the variant carries is populated from the header.
  - [ ] `500 Internal Server Error` → maps to `DomainError::ProviderError`.
  - [ ] A `200 OK` response with a body that is not valid JSON / doesn't match `OpenAIResponse`'s shape → maps to `DomainError::ProviderError` (parse failure) without panicking.
  - [ ] A wiremock response configured with a delay longer than the provider's configured client timeout → maps to `DomainError::Timeout`. Use a short configured timeout (e.g. via the injected config, not a global default) so the test runs fast.
- [ ] Add a short doc-comment block at the top of each new test file (or a `llm-gateway/tests/README.md`) stating this harness is the pattern subsequent provider (step 25 Anthropic, step 26 Gemini) and streaming (step 43) steps should extend with their own cases in the same files/style, rather than introducing a new mocking approach.
- [ ] Ensure `cargo test` and `cargo clippy --all-targets -- -D warnings` are clean with the new tests included.

## Implementation notes
- Router under test: `llm-gateway/src/adapters/inbound/rest/router.rs` builds the `Router` via `build_router(state: AppState)` where `AppState = Arc<dyn CompletionUseCase>` (see `llm-gateway/src/adapters/inbound/rest/handlers.rs:15`). By step 3, `CompletionUseCase::complete` and `list_models`/`models` are expected to be `async fn`s (or otherwise still return `Pin<Box<dyn Future<...> + Send>>`) — check the actual trait in `llm-gateway/src/ports/inbound/completion.rs` after steps 3/8 land and match your test double's signature to it exactly (do not assume the pre-step-3 synchronous `list_models() -> Vec<ModelInfo>` shape still holds verbatim).
- Test double for router tests: implement a minimal struct (e.g. `struct StubUseCase { ... }`) directly in `tests/router_test.rs` implementing whatever `CompletionUseCase` looks like post-step-3, with a way to parameterize which `DomainError` (or success) it returns per call — e.g. store a `Mutex<Option<DomainError>>` or take the desired response/error via a closure/enum set at construction time. This mirrors the existing `MockProvider` pattern in `llm-gateway/src/domain/service.rs`'s `#[cfg(test)] mod tests`, just one layer up (use-case level instead of provider level) and exercised through real HTTP instead of direct function calls.
- Router error-mapping matrix to test against comes from `llm-gateway/src/adapters/inbound/rest/handlers.rs`'s `AppError::into_response` — as of pre-step-3 code this matches: `InvalidRequest` → 400, `ModelNotFound` → 404, `KeyNotFound` → 500, `Timeout` → 504, `ProviderError` → 502. Step 3 adds `RateLimited`; confirm its match arm exists (add the minimal one if missing, per the Scope item above) before asserting 429.
- `oneshot` usage pattern: `use tower::util::ServiceExt; let response = router.clone().oneshot(Request::builder().method("POST").uri("/completions").header("content-type","application/json").body(Body::from(json_string)).unwrap()).await.unwrap();` then `assert_eq!(response.status(), StatusCode::OK);` and drain the body with `http_body_util::BodyExt::collect(response.into_body()).await.unwrap().to_bytes()` before `serde_json::from_slice`.
- OpenAI adapter under test: `llm-gateway/src/adapters/outbound/openai.rs`. Pre-step-8, `OpenAIProvider::new(key_store: Arc<dyn KeyStore>)` reads `OPENAI_BASE_URL` from the process environment internally (lines 37-40) and builds its own `reqwest::Client` with a fixed 10s `connect_timeout` (lines 42-47). Step 8's explicit-config requirement means this constructor (or a new one alongside it) must accept `base_url` (and ideally a request/response timeout) as plain arguments/config-struct fields instead of reading env vars — read the actual post-step-8 signature in this file before writing the wiremock tests, and use whatever the real API surface is (do not invent a signature that doesn't match the merged code).
- `wiremock` usage pattern: `let mock_server = wiremock::MockServer::start().await; Mock::given(method("POST")).and(path("/v1/chat/completions")).respond_with(ResponseTemplate::new(200).set_body_json(fixture)).mount(&mock_server).await;` then construct the provider with `base_url: mock_server.uri()`. For the timeout case, use `ResponseTemplate::new(200).set_delay(Duration::from_secs(N))` with the provider's configured timeout set shorter than `N`.
- `KeyStore` for the wiremock tests: either reuse a trivial stub returning a fixed dummy key (the tests don't hit a real API so the key value is irrelevant), or, if step 8's config struct folds the API key directly into the adapter config rather than requiring `KeyStore` at construction time, set it directly there — follow whatever the merged constructor actually requires.
- Keep GoDoc-equivalent Rust doc comments (`///` / `//!`) on any new non-trivial helper functions per `CLAUDE.md`'s "Rust docstrings: rustdoc on all public symbols" convention; test functions themselves don't need doc comments but a short module-level `//!` explaining the harness's intent in each new test file is good practice and satisfies the "extend this pattern" note called for in the Scope section.
- All code/comments/test names in English, per `CLAUDE.md`.
- No `schema.sql` / DB changes — this step touches only `llm-gateway/`.
