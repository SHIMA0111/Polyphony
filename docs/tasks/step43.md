# Step 43: Rust: streaming SSE for all providers + stream endpoint

## Meta
- **Type**: feature
- **Components**: llm-gateway
- **Wave**: 5 (parallel group — all steps of the same wave can run concurrently)
- **Depends on**: Step 14: Rust gateway test harness: router oneshot + wiremock provider tests | Step 25: Rust: Anthropic provider adapter | Step 26: Rust: Gemini provider adapter
- **Unlocks**: Step 51: Server: consume gateway stream + WS chunk forwarding
- **Size**: 1 PR (a few hours for one AI agent)

## Context
`phases.md` schedules streaming AI responses so the web UI can render tokens as they arrive instead of waiting for a full completion. Step 3 already reshaped the gateway's domain/ports layer specifically to make this possible without another rewrite: `llm-gateway/src/domain/model.rs` has a `CompletionChunk` struct, `llm-gateway/src/ports/outbound/provider.rs`'s `LLMProvider` and `llm-gateway/src/ports/inbound/completion.rs`'s `CompletionUseCase` both carry a `stream()` method returning `futures::future::BoxFuture<'_, Result<futures::stream::BoxStream<'static, Result<CompletionChunk, DomainError>>, DomainError>>`, and `llm-gateway/src/domain/service.rs`'s `CompletionService::stream()` already resolves the target provider via `find_provider` and delegates to it. Steps 25 and 26 added `AnthropicProvider` and `GeminiProvider` alongside `OpenAIProvider`, each with a `stream.rs` submodule (per the `{provider}/mod.rs` + `request.rs` + `stream.rs` split Step 3 established) that only contains a documented "not yet implemented" placeholder returning an error. Step 14 built the `wiremock`/`tower::oneshot` test harness (`llm-gateway/tests/router_test.rs`, `llm-gateway/tests/openai_provider_test.rs`) that every provider/streaming step is expected to extend. This step is the one that makes streaming real: it replaces all three placeholder `stream.rs` bodies with actual SSE parsing against each provider's native streaming API, and exposes a new `POST /completions/stream` gateway endpoint that Step 51 (Go: consume gateway stream + WS chunk forwarding) will call.

## Goal
After this PR, `OpenAIProvider`, `AnthropicProvider`, and `GeminiProvider` each implement `LLMProvider::stream()` for real: they issue a streaming HTTP request to their respective native streaming API, parse the provider's Server-Sent Events (or SSE-shaped) response body incrementally, and yield a `futures::stream::BoxStream` of `Result<CompletionChunk, DomainError>` as tokens arrive — no buffering of the full response before yielding the first chunk. The gateway exposes a new `POST /completions/stream` REST endpoint that accepts the same request shape as `POST /completions`, calls `CompletionUseCase::stream()`, and re-emits the resulting `CompletionChunk`s as an outbound `text/event-stream` response via `axum::response::sse::Sse`, terminated by a `data: [DONE]` sentinel event once the upstream stream completes (mirroring OpenAI's own convention, applied uniformly across all three providers so Step 51 has one contract to consume regardless of which provider served the request). Errors discovered before any bytes are sent (bad request, unknown model) still surface as ordinary HTTP error responses with the existing `AppError` status mapping; errors discovered mid-stream surface as an `event: error` SSE frame, since the HTTP status and headers are already committed by that point. Every provider's streaming path is covered by a `wiremock`-backed integration test asserting the exact sequence of `CompletionChunk`s produced from a canned SSE fixture, and the new endpoint is covered by a `router_test.rs` case using a stub `CompletionUseCase` whose `stream()` yields a scripted sequence of chunks/errors.
